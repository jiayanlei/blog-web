# React Bits 引入与重构方案

## 目标定位

当前项目已经有很明确的视觉气质：`Time Relic / Cosmic Portfolio`，也就是时间遗迹、宇宙时钟、AI 工程师作品集。React Bits 不适合作为一个“大包插件”直接塞进项目，而更适合按需吸收它的组件思想：文字动效、聚光卡片、磁性按钮、Bento 能力矩阵、局部背景动效。

本次重构目标是把项目从“沉浸式作品集首页”升级为“有博客潜力的个人技术宇宙站”：

- 首页是宇宙时钟，负责第一眼记忆点。
- 项目是时间档案，负责证明真实工程经验。
- AI 能力是仪表盘，负责表达个人方向。
- 后续博客是时间档案库，负责承载持续输出。

## React Bits 接入策略

React Bits 当前更像可复制、可定制的开源组件集合，而不是名为 `reactbits` 的 npm 包。`npm view reactbits` 返回 404，因此本项目采用“按需移植式引入”：

1. 在 `src/components/reactbits/` 下维护本项目版本的 React Bits 风格组件。
2. 只引入与当前主题强相关的组件形态，避免背景和 Three.js 主视觉互相争抢。
3. 组件 API 保持小而清晰，方便后续替换为官方代码或继续扩展。
4. 所有动效都尊重 `prefers-reduced-motion`。

首批引入组件：

- `ShinyText`：用于首页主标题和节点标题的流光文字。
- `SplitRevealText`：用于节点切换时的分字/分词入场。
- `SpotlightCard`：用于项目卡和信息卡的鼠标聚光。
- `MagicBento`：用于 AI 能力区，形成更像控制台的能力矩阵。
- `MagnetLink`：用于联系入口和 CTA，让按钮有轻量磁吸感。

## 当前项目需要完善的地方

### 1. `App.tsx` 过重

当前 `src/App.tsx` 同时承担数据、状态、页面结构和 section 渲染。短期可以保留单文件页面以降低改动风险，但需要先把数据抽到 `src/data/siteContent.ts`，让内容和视图分离。

后续建议继续拆为：

```txt
src/components/sections/
  OriginSection.tsx
  AboutSection.tsx
  StackSection.tsx
  ProjectsSection.tsx
  HighlightsSection.tsx
  ContactSection.tsx
```

### 2. 首页记忆点还可以更强

现有第一屏文案很好，但展示方式偏静态。应把主标题做成“时间裂隙里被照亮的文字”：分字入场 + 流光扫过 + 副标题延迟浮现。React Bits 的文字动画思路最适合这里。

### 3. 项目卡缺少交互反馈

当前项目卡信息完整，但鼠标经过只是静态玻璃感。建议使用 `SpotlightCard`：

- 卡片根据鼠标位置出现局部高光。
- 项目亮点作为底部“档案标签”。
- 技术栈和能力点视觉层级分开。

### 4. AI 能力区需要从列表升级为矩阵

当前四张 `highlight-card` 是均匀列表。建议改为 `MagicBento`：

- `AI 工作台` 作为大格，占两列。
- `企业知识库助手` 和 `文档解析与洞察` 作为中格。
- `Agent 自动化` 做成强调格，带轨迹感。

这会让“AI 能力”看起来像一个产品能力地图，而不是简历文本。

### 5. 联系区需要一个明确动作

当前联系区有链接，但缺少主行动按钮。建议增加：

- `mailto` 主按钮：一起做点有意思的东西。
- GitHub / 项目空间按钮。
- 下载简历按钮。

按钮使用磁吸和边缘流光，但保持安静，不做夸张跳动。

## 创意升级方向

### 时间档案叙事

每个节点不只是 section，而是一枚“时间碎片”：

- 起点：遗失的机会与坚持。
- 关于我：工程人格碎片。
- 技术栈：围绕问题旋转的星轨。
- 项目作品：被真实需求推动过的档案。
- AI 能力：未来工具的控制台。
- 寻找我：传送门。

### 后续博客形态

新增 `Time Archive` 博客页时，可以按下面结构设计：

- `AI 实践`
- `前端工程`
- `全栈系统`
- `产品思考`
- `成长日志`

文章卡片可以复用 `SpotlightCard`，文章详情页则应减少动画，强调阅读。

## 分阶段实施

### Phase 1：视觉质感与结构基础

- 新增 React Bits 风格组件层。
- 抽离站点内容数据。
- 改造首页主标题、项目卡、AI 能力矩阵、联系按钮。
- 保留现有 Three.js 星空层和滚轮节点切换。

### Phase 2：组件拆分与可维护性

- 把各节点拆成 section 组件。
- 把导航、标题、卡片抽成稳定组件。
- 建立页面级 CSS 分层，避免 `styles.css` 无限增长。

### Phase 3：博客与项目详情

- 增加本地 `posts.ts` 数据。
- 增加博客列表和文章详情。
- 项目卡增加详情入口。

### Phase 4：性能和可访问性

- 为移动端降低部分动效强度。
- 检查 Three.js 与 CSS 动效叠加后的帧率。
- 完善键盘导航、焦点态和 reduced motion。

## 第一阶段验收标准

- 项目可以正常 `npm run build`。
- 首页仍保持原来的宇宙时钟主题。
- 页面源码中已经有 React Bits 风格组件目录。
- 第一屏、项目区、AI 能力区、联系区能看到明显交互升级。
- 内容数据不再全部硬编码在 `App.tsx`。
